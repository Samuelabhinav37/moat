How it works, for the curious

The technical detail behind the claims above. Open any section.

EnforceWhat happens on every page load

Three layers act in parallel, all on your device: the network filter, the scripts that run inside the page, and a safety net for popup tabs the scripts never saw.

Network requestAny file, frame or navigation the page asks for.
Matches a built-in blocking rule?
matchBlock it, or swap in a harmless stand-in.
no matchThe request goes ahead normally.
Page scripts @ document_startHide leftover ad boxes with CSS, and add fingerprint protection if it's on.
New tab lands on a known popup domain?
matchClose the tab quietly.
no matchWatched briefly for a late redirect, then left alone.
RefreshThe live-update channel

A small set of fixes updates faster than store releases can: about 460 popup domains, an emergency block and allow list, and fixes for hiding page elements. The file list is checked against a signing key built into Moat (Ed25519), and each file against its SHA-256 hash, before anything is used. If a check fails, Moat keeps what it shipped with.

Timer firesAbout once a day. The first run waits a random 30 to 180 minutes.
Last update under 18 hours old?
freshSkip the network and use the saved copy.
staleDownload manifest.json and its signature.
Signature and hashes check out?
failsKeep the built-in lists. Try again next time.
passesApply the three files below.
A verified update feeds straight into blocking:
redirect-domainsNew blocking rules, plus the popup tab list. Both saved for restarts.
quick-fixesBlock and allow rules only. Nothing that can redirect or rewrite a request can arrive this way.
cosmetic-fixesChecked CSS selectors, used from the next page load.
TrustWhy the privacy claim holds
  • There's nothing to sell. No telemetry, no account and no server. Even a new owner would find little to make money from.
  • Updates carry data, never code. Only block and allow rules and CSS selectors arrive. Each selector goes through the same isSafeCosmeticSelector check as your own rules, with limits on length and count.
  • Signed, then hashed. Even if the hosting were taken over, the worst an attacker could do is block or allow a list of domains.
  • A strict content security policy. Every script ships inside the extension. There's no eval and no remote script.
  • It asks to read every site. An ad blocker has to see requests on every page to block them. There's no narrower permission that does the job.
ScaleWhy it holds at scale
  • No shared bottleneck. Every copy runs on its own. The browser stores handle downloads and updates, so ten thousand or ten million users is Google, Mozilla and GitHub's load, not ours.
  • The only regular download is the daily file from GitHub Pages. It's a few kilobytes and sits behind a CDN cache.
  • Chrome limits blocking rules across all your extensions combined. Moat notices when that limit is close and offers a lighter preset.
